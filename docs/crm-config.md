# Twenty CRM 配置清单（照着点）

> 目标：4 个人共用，不限制“只能看自己的客户”。  
> 原则：**一个客户一条人员，一次成交一条商机，聊一次一条沟通记录。**  
> 状态只看商机阶段，下一步只看商机的“下次跟进时间”。

## 0. 先做这三件事

1. 用管理员登录 `https://crm.aicyld.com`。
2. **Settings → Experience → Language → 中文**。
3. **Settings → Members**：邀请 3 位同事；1 个管理员，其余用 Member。  
   Member 角色关闭“数据模型、成员管理、工作流管理、安全设置”，避免误改配置。

---

## 1. 数据模型总览

```
人员 People（一个客户一条）
   │ 1:N
   ├──────────────► 商机 Opportunities（一次成交周期一条）
   │                      │ 1:N
   └──────────────► 沟通记录 Communication（每聊一轮一条）
```

| 对象 | 类型 | 一条记录代表 | 用途 |
|---|---|---|---|
| 人员 People | 标准 | 一个客户 | 联系方式、来源渠道、开发人、备注 |
| 商机 Opportunities | 标准 | 一次成交周期 | 阶段、当前轮次、下次跟进、金额 |
| 沟通记录 Communication | 自定义 | 一轮沟通 | 第几轮、谁聊的、聊了什么、结果 |

> 不要新建“客户”对象代替 People。Twenty 的邮件/日历同步只认 People、Companies、Opportunities。

---

## 2. 人员 People

标准字段直接用：姓名、手机、邮箱、公司、职位、城市。

新增自定义字段（Settings → Data Model → People → + 新字段）：

| 字段名 | 类型 | 选项/说明 |
|---|---|---|
| 微信号 | 文本 | 客户微信/企微号 |
| 来源渠道 | 单选 | 抖音 / 小红书 / 视频号 / 微信 / 转介绍 / 线下 / 官网 / 其他 |
| 开发人 | 单选 | 4 位同事的名字；建档时填 A，之后不变 |
| 备注 | 长文本 | 客户背景、偏好、禁忌 |

> **人员对象没有“负责人”字段**（Twenty v2.56 的标准 People 对象不提供 Owner）。  
> “当前负责人”统一看**商机**上的负责人；交接只改商机，不改人员。开发人保留 A，用来算渠道和提成。

**人员页布局建议**：姓名、手机、微信、来源渠道、开发人、备注；关联列表放“商机”和“沟通记录”。

---

## 3. 商机 Opportunities

标准字段直接用：名称、阶段、金额、预计成交日期、负责人。

新增自定义字段：

| 字段名 | 类型 | 选项/说明 |
|---|---|---|
| 当前轮次 | 数字 | 1/2/3/4…每次沟通后更新 |
| 下次跟进时间 | 日期和时间 | **日常唯一认这个字段**；没有它就不算排好下一步 |
| 交接摘要 | 长文本 | 需求 / 预算 / 决策人 / 顾虑 / 已承诺事项 |
| 流失原因 | 单选 | 价格 / 不需要 / 竞品 / 失联 / 其他 |

标准“负责人（Owner）”= **当前成交负责人**。交接时从 A 改成 B。

**商机命名建议**：`客户名-意向产品/需求`，例如“张三-少儿编程年课”。

### 阶段（改标准“阶段”字段的选项）

| 阶段 | 什么时候用 | 负责人 |
|---|---|---|
| 新线索 | 刚建联，还没首聊 | A |
| 首轮沟通 | 首聊中/聊完待判断 | A |
| 待交接 | 有意向，等 B 接手 | A |
| 二轮跟进 | B 已接手，2/3/4 轮都在这里 | B |
| 方案/报价 | 进入报价/合同 | B |
| 成交 | 已签约/付款 | B |
| 流失 | 明确不做/长期失联 | B |

> **不要给第 2、3、4 轮各建一个阶段。**  
> 阶段表示销售进展，轮次表示聊了几次；否则看板会变成十几列。

---

## 4. 沟通记录 Communication（自定义对象）

Settings → Data Model → + 新对象：

- 单数名称：`沟通记录`
- 复数名称：`沟通记录`
- 图标：选一个消息/记录类图标

### 字段

| 字段名 | 类型 | 说明 |
|---|---|---|
| 名称 | 文本（默认） | 建议填 `客户名-第N轮-MMDD` |
| 关联客户 | 关系 → 人员 | 多对一；目标字段名在人员上叫“沟通记录” |
| 关联商机 | 关系 → 商机 | 多对一；目标字段名在商机上叫“沟通记录” |
| 轮次 | 数字 | 1/2/3/4… |
| 沟通时间 | 日期和时间 | 实际发生时间 |
| 渠道 | 单选 | 电话 / 微信 / 企业微信 / 面谈 / 邮件 / 其他 |
| 沟通人 | 单选 | 4 位同事的名字；系统还会自动记录创建人 |
| 沟通内容 | 长文本/富文本 | 按下面模板写 |
| 客户反馈 | 长文本 | 客户的顾虑、异议、原话 |
| 本轮结果 | 单选 | 继续跟进 / 待报价 / 已成交 / 流失 / 暂缓 |
| 意向等级 | 单选（可选） | 高 / 中 / 低 / 无 |
| 附件 | 文件（如版本支持） | 截图、合同、报价单 |

### 沟通内容模板（统一写法，交接不用问人）

```
客户说了什么：
顾虑/异议：
我方回应：
下一步：
```

## 5. 关系怎么建

在 **商机** 上建关系字段：

- 字段：`关联客户`
- 类型：关系
- 目标对象：人员
- 关系类型：多对一（多条商机 → 一个人员）
- 目标字段名（在人员上显示）：`商机`

在 **沟通记录** 上建两个关系字段：

- `关联客户`：目标对象人员，多对一，人员上的目标字段名 `沟通记录`
- `关联商机`：目标对象商机，多对一，商机上的目标字段名 `沟通记录`

建完后：

- 人员详情页会多出“商机”和“沟通记录”两个关联列表；
- 商机详情页会多出“沟通记录”时间线。

## 6. 五个核心视图

在对应对象左上角的视图菜单里 **+ 新建视图**。

| 视图 | 对象 | 筛选 | 排序 | 谁用 |
|---|---|---|---|---|
| **线索池** | 人员 | 全部客户 | 创建时间 从新到旧 | 主管/A |
| **我的待跟进** | 商机 | 负责人 = 刘羽驰（管理员视角）；阶段 ≠ 成交、流失 | 下次跟进时间 从早到晚 | A/B 每天先看 |
| **今日已约** | 商机 | 下次跟进时间 = 今天 | 下次跟进时间 从早到晚 | A/B |
| **二轮以上未成交** | 商机 | 当前轮次 ≥ 2；阶段 ≠ 成交、流失 | 当前轮次 从多到少 | 主管 |
| **销售管道** | 商机 | 无（看板按阶段） | 按阶段分组 | 全员 |
| **沟通流水** | 沟通记录 | 全部 | 沟通时间 从新到旧 | 全员查历史 |
| **渠道分析** | 人员 | 全部 | 创建时间 从新到旧 | 老板/主管 |

> “我的待跟进”目前按管理员刘羽驰的负责人 ID 过滤。其他 3 位同事在视图菜单里**复制视图**，把负责人筛选改成自己即可；等 4 人都加入后可以一人一个同名视图。

**列建议：**

- 我的待跟进：商机名称、关联客户、阶段、当前轮次、下次跟进时间、负责人
- 二轮以上未成交：商机名称、关联客户、阶段、当前轮次、金额、下次跟进时间、负责人
- 沟通流水：关联客户、轮次、沟通时间、渠道、沟通人、本轮结果、沟通内容

再建一个 **仪表盘**：按来源渠道统计商机数量、成交数量。老板每周看一次。

## 7. 工作流 1：交接任务（必配）

Settings → Workflows → + 新建工作流。

- **触发器**：记录已更新 → 对象选“商机” → 监听字段选“阶段”
- **条件/筛选**：阶段 = 待交接
- **动作 1：创建记录**
  - 对象：任务
  - 名称：`接手跟进：{{trigger.object.name}}`
  - 指派人：商机负责人（`{{trigger.object.owner}}`）
  - 关联商机：当前商机
  - 截止日期：明天 10:00（如果变量不支持，先留空）
- **动作 2（可选）**：发送电子邮件给商机负责人  
  需要先在 Settings → Accounts 连接邮箱；没配就先不用。
- **激活**，然后用一条测试商机走一遍：阶段改成“待交接”，看 B 是否收到任务。

> 负责人由 A **手动选 B**，不要让工作流做自动轮询分配。4 个人没必要，动态分配也容易出错。

## 8. 工作流 2：每日提醒（可选，先用视图）

先用“我的待跟进”视图即可。等团队用顺了，再加：

- 触发器：定时，每天 09:00
- 搜索商机：阶段 ≠ 成交/流失，下次跟进时间 ≤ 今天
- 给负责人发邮件/建任务

第一周不建议上，避免提醒太多被忽略。

## 9. 权限

- 4 个人共享客户，**不需要行级权限**，免费版够用。
- 1 个管理员；其余 3 个 Member。
- Member 关闭：数据模型、成员管理、工作流管理、安全设置。
- “每人只能看自己的客户”是 Organization 付费功能；你们不需要。

---

## 10. 录入规则（贴在工位）

1. **建联 10 分钟内**：建人员（来源渠道、开发人=A）+ 建商机（阶段=新线索，负责人=A）。
2. **首聊当天**：建第 1 条沟通记录（轮次=1），商机阶段=首轮沟通，填下次跟进时间。
3. **有意向**：商机阶段=待交接、负责人=B、写交接摘要。
4. **B 接手 24 小时内**：完成第 2 轮；每聊一次当天建一条记录，轮次递增。
5. **每次沟通后**：更新商机“当前轮次”“下次跟进时间”“阶段”。
6. **成交当天**：阶段=成交，填金额、成交日期；流失填原因。

**一页纸规则：**

> 一个客户一条人员，一次成交一条商机，聊一次一条沟通记录。  
> 状态只看商机阶段，下一步只看商机下次跟进，聊天内容当天录。

---

## 11. 不要做的事

- 不要新建“客户”对象代替 People（邮件/日历同步会失效）。
- 不要用 Notes 代替沟通记录（不能按轮次/结果/下次跟进筛选）。
- 不要一轮一个阶段（看板会爆炸）。
- 不要找“人员”的负责人字段；负责人在商机上。
- 不要把 Twenty 放到 `www.aicyld.com/crm` 子路径（官方不支持）。
- 不要用 `latest` 镜像（升级失控）。
- 不要把 `.env` 提交到 Git。
